# Sesión 2026-06-19 — Fix 2FA (pantalla de setup daba error)

## Objetivo

Resolver "2FA da error" (bug crítico que bloqueaba producción, BUG-001).

## Causa raíz (una sola línea)

`app/Controllers/TotpController.php:73` llamaba al helper de QR sin
backslash:

```php
$qrImgTag = QrHelper::imgTagFromUrl($uri, 220, '...');   // ❌
```

`TotpController` está en namespace `App\Controllers`, pero `QrHelper`
(en `core/Helpers/QrHelper.php`) **no declara namespace** → vive en el
namespace **global**. Una llamada estática sin `\` se resuelve contra el
namespace actual → PHP buscaba `App\Controllers\QrHelper` → **Fatal:
"Class not found"** al abrir `/totp/setup`. Por eso la pantalla de
configurar 2FA "daba error".

Funcionaba en facturas porque ahí `QrHelper::imgTag()` se llama desde
**vistas**, que se incluyen en el namespace global (no en una clase).

## Fix

```php
$qrImgTag = \QrHelper::imgTagFromUrl($uri, 220, '...');  // ✅ backslash
```

Una línea. Único sitio afectado (grep confirmó que ningún otro
controller/clase llama `QrHelper::` sin `\`; las vistas están OK).

## Verificación

- Reproducido el fatal en local simulando el namespace `App\Controllers`.
- Tras el fix, ejecutado bajo el **PHP 8.3 real de la web** (vía script
  HTTP temporal): genera el QR OK (tag len=295).
- Usuario confirmó: la pantalla de setup carga el QR. ✅

## Qué NO era (descartado con pruebas, no por intuición)

- **core/Totp.php**: 100% correcto. Test propio: genera código válido,
  verifica, rechaza incorrectos, backup codes con y sin guion. Todo OK.
- **Columnas BD** (`two_fa_secret/enabled/backup_codes`): existen en
  producción (migración 028 sí aplicada). 0 usuarios con 2FA activo.
- **CSRF**: las vistas usan `csrf_field()` correctamente.
- **AuthController login**: la bifurcación 2FA (`_2fa_pending` +
  redirect a `totp/verify`) está bien.

## Falso positivo a recordar

El `php` de **CLI** del servidor Hostinger es **PHP 7.4.33**; la **web
(PHP-FPM) es 8.3.30**. Al testear por CLI saltó un parse error en
`Totp.php` por `catch (\Throwable)` (non-capturing catch, sintaxis 8.0+)
— **irrelevante**: la web corre 8.3. → Para verificar comportamiento
real hay que ejecutar bajo el PHP de la web (script HTTP temporal), no
con `php` CLI. Ver [[../Arquitectura/Despliegue-Hostinger]].
